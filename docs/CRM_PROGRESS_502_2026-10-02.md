# Lỗi 502 ở trang "Quản lý tiến độ" của crm.securityzone.vn (phát hiện 2026-10-02) — CHƯA SỬA

**Trạng thái: chưa sửa. Đã tìm ra nguyên nhân và cách sửa, chờ người có quyền làm PR vào `main`.**

## Triệu chứng
- Trang `https://crm.securityzone.vn/all-platform/crm/progress` (và bản chép trong MSC `/msc-dev/all-platform/crm/progress`) hiện lỗi:
  `{'message': 'JSON could not be generated', 'code': 502, 'hint': 'Refer to full message for details', 'details': "b'<html>... 502 Bad Gateway ... openresty ...'"}`
- Các CRM khác (Markee `crm-module`, `crm-cloudgate`) **không lỗi**. Chỉ securityzone lỗi.
- Log backend vẫn ghi `GET /api/all-platform/progress/alerts 200 OK` nên nhìn log tưởng không có lỗi (xem "Cơ chế").

## Cơ chế (vì sao log vẫn `200 OK`)
`routers/progress.py`: mọi lỗi bị bắt `except Exception as e: return BaseResponse(success=False, message=str(e))`
→ HTTP 200 nhưng body `success:false`, `message` = chuỗi lỗi ở trên. Giao diện hiện đúng chuỗi đó.

## Nguyên nhân gốc
Truy vấn gửi sang Supabase REST kèm danh sách ID (`.in_("lead_id", [...])`) quá dài → địa chỉ yêu cầu dài vượt giới hạn của
cổng (openresty) trước kho dữ liệu → trả `502 Bad Gateway` (HTML, không phải JSON → thư viện báo "JSON could not be generated").

- Hàm lỗi: `get_management_alerts` → `_leads_since_map` (`progress_service.py` ~dòng 219) → `_query_in_batches` → bảng `crm_lead_activity_log`.
- Team đã từng sửa lỗi cùng loại (commit `d8dfeb4c`, 25/9: "batch .in_() queries to avoid Supabase 502 on large ID lists") bằng cách chia lô
  `_IN_BATCH_SIZE = 150`. **150 vẫn quá lớn với securityzone** (150 UUID ≈ 5.800 ký tự). Mọi `.in_()` trong file đều đã chia lô, nên lỗi là do cỡ lô, không phải do quên chia.

## Bằng chứng (chạy trên máy CRM, container `crm-securityzone-backend`, chỉ đọc)
- Gọi từng hàm tiến độ: `get_progress_overview`, `list_progress_teams`, `list_progress_quotes`, `list_progress_records` → OK. **`get_management_alerts` → LỖI** (traceback chỉ đúng `_leads_since_map`).
- Có 152 lead đang xử lý. Thử cùng truy vấn với cỡ lô khác nhau:

| Cỡ lô | Kết quả |
|---|---|
| 150 | **LỖI** sau 5,7 giây |
| 50 | OK, 152 dòng, 0,1 giây |
| 20 | OK, 152 dòng, 0,2 giây |
| 10 | OK, 152 dòng, 0,4 giây |

→ Không phải bảng chậm hay kết quả quá lớn; chỉ cần lô nhỏ hơn là chạy.

## Cách sửa (chưa làm)
Đổi `_IN_BATCH_SIZE = 150` thành `50` (dòng 89) trong **cả 4 file**:
- `crm-securityzone/backend/app/modules/all_platform/services/progress_service.py`
- `crm-module/backend/app/modules/all_platform/services/progress_service.py`
- `crm-cloudgate/backend/app/modules/all_platform/services/progress_service.py`
- `linkedin_group_crawler/app/modules/all_platform/services/progress_service.py`

Ảnh hưởng: kết quả không đổi; chậm thêm vài giây nếu có hàng nghìn lead; không ghi dữ liệu. Merge vào `main` sẽ tự deploy lại 3 backend CRM (khởi động lại vài giây mỗi bản; `linkedin_group_crawler` deploy thủ công qua "Deploy App (Production)").

**Không sửa tay trên máy chủ**: lần deploy sau (`rsync --delete`) sẽ ghi đè.

## Kiểm tra sau khi sửa
Chạy lại trên máy CRM, mọi dòng phải `OK`:
```bash
docker exec -i crm-securityzone-backend python - <<'EOF' 2>/dev/null
import traceback
from app.modules.all_platform.services import progress_service as ps
user = {"id": "debug", "role": "admin", "email": "debug@local"}
for name in ["get_progress_overview", "list_progress_teams", "list_progress_quotes", "get_management_alerts", "list_progress_records"]:
    try:
        getattr(ps, name)(user); print("OK  ", name)
    except Exception:
        print("LỖI ", name); traceback.print_exc()
EOF
```
Rồi mở lại `crm.securityzone.vn/all-platform/crm/progress` (admin hoặc leader).
